    Módulo 01 — Fundação

    Fundamentos do JavaScript

    JavaScript não é apenas "a linguagem que anima páginas". É uma linguagem dinamicamente tipada, multi-paradigma e single-threaded, com um modelo de execução assíncrona que a diferencia de quase tudo que veio antes dela. Entender essa base é o que separa quem escreve código que funciona de quem escreve código que se sustenta.

    Declarando variáveis: var, let e const

    As três formas de declarar uma variável coexistem no motor, mas têm regras de escopo e hoisting completamente diferentes. Na prática moderna, const é o padrão, let é a exceção quando a variável precisa mudar, e var é praticamente legado.

    variaveis.js
    // var é function-scoped e sofre hoisting com valor "undefined"
var nome = "Ana";

// let é block-scoped, não pode ser redeclarada no mesmo escopo
let idade = 28;
idade = 29; // pode ser reatribuída

// const é block-scoped e imutável na ligação (o valor pode mudar se for objeto)
const PI = 3.14159;
const usuario = { nome: "Ana" };
usuario.nome = "Bia"; // válido: a referência não mudou
    Palavra-chaveEscopoHoistingReatribuição
    varFunçãoSim, inicializada como undefinedSim
    letBlocoSim, mas em "temporal dead zone"Sim
    constBlocoSim, mas em "temporal dead zone"Não

    Tipos primitivos e coerção

    JavaScript tem sete tipos primitivos: string, number, boolean, undefined, null, bigint e symbol. Todo o resto — arrays, objetos, funções — é do tipo object por baixo dos panos. A coerção de tipos acontece quando operadores forçam a conversão implícita entre eles.

    coercao.js
    1 + "1"        // "11" — number vira string
"5" - 1        // 4   — string vira number
0 == "0"       // true  — coerção de tipo
0 === "0"      // false — sem coerção, tipos diferentes
Boolean("")     // false — string vazia é falsy
Boolean("0")    // true  — string "0" é truthy!

    Erro comum

    Usar == (igualdade solta) por hábito. Prefira sempre === (igualdade estrita) — ela compara valor e tipo, eliminando uma classe inteira de bugs sutis de coerção.

    Por que isso importa

    Entender truthy e falsy evita bugs em condicionais: apenas false, 0, "", null, undefined e NaN são falsy — absolutamente tudo mais, incluindo "0" e arrays vazios [], é truthy.

    Módulo 02 — Fluxo de execução

    Estruturas de Controle & Funções

    Controlar o fluxo de execução e organizar comportamento em funções reutilizáveis é o que transforma uma sequência de instruções em um programa de verdade.

    Condicionais e laços

    controle.js
    for (let i = 0; i < 3; i++) {
  console.log(i); // 0, 1, 2
}

const frutas = ["maçã", "pera", "uva"];
for (const fruta of frutas) {
  console.log(fruta); // itera sobre valores
}

switch (status) {
  case "ativo":
    console.log("Usuário ativo");
    break;
  default:
    console.log("Status desconhecido");
}

    Três formas de declarar uma função

    A escolha entre elas não é estética: cada uma tem comportamento diferente de hoisting e de ligação do this — este último é aprofundado no Módulo 05.

    funcoes.js
    // declaração de função — sofre hoisting completo
function somar(a, b) {
  return a + b;
}

// expressão de função — não sofre hoisting
const subtrair = function(a, b) {
  return a - b;
};

// arrow function — sintaxe enxuta, sem "this" próprio
const multiplicar = (a, b) => a * b;

// parâmetros default e rest
function criarPedido(cliente, ...itens) {
  return { cliente, itens };
}
    FormaHoistingthis próprioUso típico
    DeclaraçãoSim, completoSimFunções nomeadas de alto nível
    ExpressãoNãoSimAtribuição condicional, callbacks
    Arrow functionNãoNão (herda do escopo léxico)Callbacks curtos, métodos que precisam do this externo

    Regra prática

    Se a função precisa do seu próprio this (métodos de objeto, construtores), use função tradicional. Se ela só precisa "emprestar" o this do escopo ao redor (callbacks dentro de métodos), use arrow function.

    Módulo 03 — Estruturas de dados

    Arrays, Objetos & Desestruturação

    Quase todo dado que circula em uma aplicação JavaScript passa por um array ou um objeto. Dominar os métodos funcionais de array e a sintaxe de desestruturação elimina a maior parte dos loops manuais e do código repetitivo.

    Métodos funcionais de array

    arrays.js
    const produtos = [
  { nome: "Mouse", preco: 80 },
  { nome: "Teclado", preco: 220 },
  { nome: "Monitor", preco: 950 },
];

const nomes = produtos.map(p => p.nome);
const caros = produtos.filter(p => p.preco > 100);
const total = produtos.reduce((soma, p) => soma + p.preco, 0);
const monitor = produtos.find(p => p.nome === "Monitor");
const temCaro = produtos.some(p => p.preco > 500);
    MétodoRetornaUso
    map()Novo arrayTransformar cada item
    filter()Novo arraySelecionar itens por condição
    reduce()Valor únicoAcumular/agregar dados
    find()Item ou undefinedBuscar o primeiro que casa
    sort()Array (muta o original!)Ordenar — sempre passe um comparador

    Desestruturação e spread

    destructuring.js
    const usuario = { nome: "Léo", cidade: "Recife", idade: 31 };

// desestruturação de objeto, com renomeação e default
const { nome, cidade: local = "desconhecida" } = usuario;

// desestruturação de array
const [primeiro, segundo] = ["a", "b", "c"];

// spread para copiar/mesclar sem mutar o original
const atualizado = { ...usuario, idade: 32 };
const combinada = [...frutas, "manga"];

    Por que isso importa

    Spread (...) cria uma cópia rasa (shallow copy). Objetos aninhados continuam sendo referenciados — um erro comum ao tentar imutabilidade "de verdade" em estruturas profundas.

    Módulo 04 — Interface com a página

    DOM, Eventos & Manipulação

    O DOM (Document Object Model) é a representação em árvore do HTML que o JavaScript pode ler e modificar em tempo real. É essa ponte que transforma uma página estática em uma aplicação interativa.

    Selecionando e criando elementos

    dom.js
    const botao = document.querySelector(".botao-salvar");
const itens = document.querySelectorAll(".item");

const card = document.createElement("div");
card.classList.add("card", "card--novo");
card.textContent = "Olá, DOM";
document.body.appendChild(card);

    Eventos e delegação

    Anexar um listener a cada item de uma lista longa é ineficiente e não funciona para itens adicionados depois. A delegação de eventos resolve isso: você escuta no elemento pai e usa event.target para identificar o item real que disparou o evento.

    eventos.js
    const lista = document.querySelector(".lista");

lista.addEventListener("click", (event) => {
  const item = event.target.closest(".item");
  if (!item) return; // clique fora de um item — ignora

  console.log("Item clicado:", item.dataset.id);
});
    EventoDispara quando
    clickClique do usuário
    inputValor de um campo muda, a cada tecla
    submitFormulário é enviado
    DOMContentLoadedHTML foi totalmente parseado

    Atenção

    Eventos como click fazem bubbling: sobem do elemento clicado até o document. Use event.stopPropagation() com moderação — abusar dele quebra a delegação de eventos em componentes pais.

    Módulo 05 — O motor por dentro

    Escopo, Closures & this

    Estes são os conceitos que mais geram confusão em JavaScript — e também os que mais distinguem quem entende a linguagem de quem apenas a usa por tentativa e erro.

    Closures: funções que lembram

    Uma closure acontece quando uma função "lembra" o escopo léxico em que foi criada, mesmo depois que esse escopo já terminou de executar.

    closures.js
    function criarContador() {
  let contagem = 0;

  return function() {
    contagem++;
    return contagem;
  };
}

const contador = criarContador();
contador(); // 1
contador(); // 2 — "contagem" persiste entre chamadas

    Por que isso importa

    Closures são a base de padrões como debounce, memoization, módulos com estado privado e a maioria dos custom hooks de bibliotecas de UI modernas.

    this: o parâmetro implícito

    O valor de this não é fixo — ele depende de como a função é chamada, não de onde foi definida (exceto em arrow functions).

    this.js
    const pessoa = {
  nome: "Rui",
  saudar() {
    console.log(`Olá, sou ${this.nome}`); // this = pessoa
  },
};

const saudarSolto = pessoa.saudar;
saudarSolto(); // this = undefined (modo estrito) — erro!

// bind fixa o valor de "this" permanentemente
const saudarFixo = pessoa.saudar.bind(pessoa);
saudarFixo(); // funciona: this = pessoa

    Erro comum

    Passar um método de objeto diretamente como callback (setTimeout(pessoa.saudar, 1000)) "perde" o this. Use uma arrow function wrapper (() => pessoa.saudar()) ou .bind().

    Módulo 06 — Tempo e concorrência

    Assincronismo: Promises & Async/Await

    JavaScript é single-threaded, mas não é bloqueante. Operações demoradas — requisições de rede, temporizadores, leitura de arquivos — são delegadas ao ambiente (navegador ou Node) e retornam via fila de callbacks, sem travar a thread principal.

    Do callback hell às Promises

    promises.js
    function buscarUsuario(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) resolve({ id, nome: "Ana" });
      else reject(new Error("ID inválido"));
    }, 800);
  });
}

buscarUsuario(1)
  .then(usuario => console.log(usuario))
  .catch(erro => console.error(erro))
  .finally(() => console.log("Concluído"));

    async/await: promises com sintaxe síncrona

    async.js
    async function carregarPerfil(id) {
  try {
    const usuario = await buscarUsuario(id);
    const posts = await buscarPosts(usuario.id);
    return { usuario, posts };
  } catch (erro) {
    console.error("Falha ao carregar perfil:", erro.message);
    throw erro;
  }
}

// executando promises em paralelo, não em série
const [usuarios, produtos] = await Promise.all([
  buscarUsuarios(),
  buscarProdutos(),
]);
    Método estáticoComportamento
    Promise.all()Resolve quando todas resolverem; rejeita se uma rejeitar
    Promise.allSettled()Sempre resolve, com status de cada uma (fulfilled/rejected)
    Promise.race()Resolve/rejeita assim que a primeira terminar
    Promise.any()Resolve com a primeira que tiver sucesso

    Regra prática

    Se duas chamadas assíncronas não dependem uma da outra, nunca as encadeie com await sequencial — dispare-as juntas com Promise.all() para paralelizar o tempo de espera.

    Módulo 07 — Organização de objetos

    Protótipos & Classes

    JavaScript usa herança prototípica — todo objeto tem uma referência interna a outro objeto (seu protótipo), formando uma cadeia. A sintaxe class introduzida no ES6 não muda esse modelo; ela é syntactic sugar sobre ele.

    A cadeia de protótipos

    prototipos.js
    const animal = {
  falar() { console.log(`${this.nome} faz um som`); }
};

const cachorro = Object.create(animal);
cachorro.nome = "Rex";
cachorro.falar(); // "Rex faz um som" — herdado via protótipo

    Classes: sintaxe moderna, mesmo motor

    classes.js
    class Animal {
  #energia = 100; // campo privado — só acessível dentro da classe

  constructor(nome) {
    this.nome = nome;
  }

  falar() {
    console.log(`${this.nome} faz um som`);
  }

  get energia() {
    return this.#energia;
  }

  static criarSelvagem() {
    return new Animal("Selvagem");
  }
}

class Cachorro extends Animal {
  falar() {
    super.falar();
    console.log(`${this.nome} late: Au au!`);
  }
}

const rex = new Cachorro("Rex");
rex.falar();

    Por que isso importa

    Campos privados (#campo) são reforçados pelo próprio motor JavaScript — diferente da convenção antiga de prefixar com underscore (_campo), que era só uma combinação, não uma barreira real.

    Módulo 08 — Escala e ecossistema

    Módulos ES6+ & Ecossistema Moderno

    Nenhuma aplicação real vive em um único arquivo. Módulos ES6 padronizaram como o código JavaScript se organiza, se importa e se compartilha entre arquivos, pacotes e times.

    import / export

    matematica.js
    export function somar(a, b) {
  return a + b;
}

export const PI = 3.14159;

export default function calcular() { /* ... */ }
    app.js
    import calcular, { somar, PI } from "./matematica.js";
import * as matematica from "./matematica.js";

    No navegador, módulos exigem <script type="module"> — isso ativa escopo isolado por arquivo, strict mode automático e carregamento assíncrono nativo, sem poluir o escopo global.

    FerramentaCategoriaPapel
    Vite / esbuildBundler/dev serverEmpacota módulos e acelera o ciclo de desenvolvimento
    BabelTranspiladorConverte JS moderno para versões compatíveis com navegadores antigos
    npm / pnpmGerenciador de pacotesInstala e versiona dependências de terceiros
    TypeScriptSuperset tipadoAdiciona tipagem estática que é removida na compilação

    Módulos vs Scripts clássicos

    Scripts tradicionais compartilham um único escopo global — variáveis de um arquivo vazam para outro. Módulos ES6 são isolados por padrão: tudo que não é explicitamente exportado permanece privado ao arquivo.

    Módulo 09 — A fronteira funcional

    Iteradores, Generators & Padrões Funcionais

    Além dos loops comuns, JavaScript expõe um protocolo de iteração customizável e funções geradoras capazes de pausar e retomar sua própria execução — a base de bibliotecas de streams, efeitos assíncronos e estruturas de dados preguiçosas.

    O protocolo iterável

    iteradores.js
    const faixa = {
  inicio: 1,
  fim: 3,
  [Symbol.iterator]() {
    let atual = this.inicio;
    const fim = this.fim;
    return {
      next() {
        return atual <= fim
          ? { value: atual++, done: false }
          : { value: undefined, done: true };
      }
    };
  }
};

for (const n of faixa) console.log(n); // 1, 2, 3

    Generators: iteradores com sintaxe declarativa

    generators.js
    function* contarAte(max) {
  for (let i = 1; i <= max; i++) {
    yield i; // pausa a execução aqui até o próximo .next()
  }
}

const gerador = contarAte(3);
gerador.next(); // { value: 1, done: false }
gerador.next(); // { value: 2, done: false }

// generators também funcionam com async, para streams assíncronos
async function* paginasDaApi(url) {
  let proxima = url;
  while (proxima) {
    const res = await fetch(proxima);
    const dados = await res.json();
    yield dados.itens;
    proxima = dados.proximaPagina;
  }
}

    Padrões funcionais: composição e currying

    funcional.js
    const curry = fn => (...args) =>
  args.length >= fn.length
    ? fn(...args)
    : (...resto) => curry(fn)(...args, ...resto);

const somar3 = (a, b, c) => a + b + c;
const somarCurried = curry(somar3);
somarCurried(1)(2)(3); // 6

// composição: combina funções pequenas em um pipeline
const compor = (...fns) => x => fns.reduceRight((v, f) => f(v), x);

    Por que isso importa

    Generators assíncronos são o mecanismo por trás de bibliotecas de streaming de dados e de efeitos observáveis — entender yield é o que torna código de fila e paginação legível sem gerenciar estado manualmente.

    Módulo 10 — Sob o capô do motor

    Event Loop, Performance & APIs Avançadas

    Entender exatamente como o motor JavaScript decide o que executar e quando é o que permite prever comportamento assíncrono, evitar travamentos de UI e diagnosticar vazamentos de memória.

    Call stack, microtasks e macrotasks

    O motor executa uma única call stack por vez. Quando ela esvazia, o event loop consulta primeiro a fila de microtasks (promises, queueMicrotask) até ela esvaziar por completo, e só então processa uma macrotask (timers, eventos de I/O) por ciclo.

    eventloop.js
    console.log("1 — síncrono");

setTimeout(() => console.log("4 — macrotask"), 0);

Promise.resolve().then(() => console.log("3 — microtask"));

console.log("2 — síncrono");

// ordem real de saída: 1, 2, 3, 4
// microtasks sempre esvaziam antes da próxima macrotask
    MicrotaskMacrotask
    ExemplosPromise.then, queueMicrotasksetTimeout, setInterval, eventos de I/O
    PrioridadeSempre esvazia primeiroUma por ciclo do loop
    RiscoPode causar starvation de macrotasks se recursivaAtraso perceptível se a fila estiver cheia

    Controlando frequência: debounce e throttle

    performance.js
    function debounce(fn, espera) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), espera);
  };
}

const buscarComDebounce = debounce(termo => buscarApi(termo), 300);
inputBusca.addEventListener("input", e => buscarComDebounce(e.target.value));

    APIs de observação nativas

    APIObserva
    IntersectionObserverQuando um elemento entra/sai da viewport — base de lazy loading e scroll infinito
    MutationObserverAlterações na árvore do DOM
    ResizeObserverMudanças de tamanho de um elemento
    Web WorkersExecutam JS em uma thread separada, sem travar a UI

    Vazamentos de memória comuns

    Listeners de evento nunca removidos, closures que retêm referências desnecessárias e setInterval sem clearInterval são as três causas mais frequentes de memory leak em aplicações JavaScript de longa duração.

    Nota final

    JavaScript evolui rápido, mas os fundamentos deste material — escopo, closures, protótipos, event loop — não mudam. Domine a base; os recursos de ponta se tornam triviais de aprender quando a fundação está sólida.

    Referência rápida

    Glossário

    Termos técnicos usados ao longo da apostila, para consulta rápida sem precisar voltar ao módulo original.

    Hoisting
    Comportamento em que declarações de variáveis e funções são "içadas" para o topo do escopo antes da execução.
    Closure
    Função que retém acesso às variáveis do escopo em que foi criada, mesmo após esse escopo terminar.
    Event Loop
    Mecanismo que gerencia a execução de código, coleta e processa eventos, e executa tarefas da fila.
    Promise
    Objeto que representa a eventual conclusão (ou falha) de uma operação assíncrona.
    Protótipo
    Objeto do qual outro objeto herda propriedades e métodos via a cadeia de protótipos.
    this
    Referência dinâmica ao contexto de execução de uma função, determinada por como ela é chamada.
    Callback
    Função passada como argumento para ser executada posteriormente por outra função.
    Generator
    Função especial (function*) capaz de pausar e retomar sua execução com yield.
    Microtask
    Tarefa de altíssima prioridade (promises) executada antes de qualquer macrotask.
    Macrotask
    Tarefa de prioridade normal (timers, eventos de I/O), processada uma por ciclo do event loop.
    Módulo ES6
    Arquivo JavaScript com escopo isolado, que exporta e importa código via import/export.
    Currying
    Técnica funcional que transforma uma função de múltiplos argumentos em uma sequência de funções de um argumento.
    Debounce
    Padrão que atrasa a execução de uma função até que um intervalo de inatividade tenha passado.
    WeakMap
    Estrutura de chave-valor cujas chaves são referenciadas fracamente, permitindo coleta de lixo automática.
    Garbage Collection
    Processo automático do motor que libera memória de objetos que não têm mais referências alcançáveis.
    IIFE
    Immediately Invoked Function Expression — função anônima executada imediatamente após ser definida.
